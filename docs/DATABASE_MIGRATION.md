# Database

## The `link` schema

Defined in `server/db/schema.ts`. Migrations are generated by drizzle-kit into `server/db/migrations/` and applied by `npm run db:migrate`, with the migrations table at `link.__drizzle_migrations`.

**Conventions:**
- Money is `bigint` cents (`*_minor`); positive means inflow.
- Calendar dates are `date`. Instants are `timestamptz`.
- Every user-owned table has `user_id`, a foreign key to `link.users` with `ON DELETE CASCADE`, so deleting a user removes everything.
- Provider ids (`provider_id`, `item_id`, `provider_account_id`) are separate from internal UUIDs.

**Idempotency constraints:**
- `transactions (account_id, provider_id)`
- `connections (provider, item_id)`
- `accounts (connection_id, provider_account_id)`
- `recurring (user_id, key)`
- `recommendations (user_id, fingerprint)`
- `webhook_events (provider, event_key)`
- `jobs (dedupe_key) WHERE status = 'queued'`

| Group | Tables |
|---|---|
| Identity | `users`, `facts` (planning inputs with provenance), `preferences`, `api_tokens` (hashed API tokens; `access` is `read` or `write`), `businesses` (owner share, tax set-aside, count-toward-goals) |
| Connections | `connections` (encrypted token, cursor, health, `plaid` item), `accounts` (`plaid`: the account, liability, holdings and investment transactions as Plaid sent them), `balance_history` |
| Transactions | `transactions` (source facts + enrichment), `splits`, `rules`, `corrections`, `recurring` |
| Planning | `goals`, `goal_progress`, `budgets` (versioned), `scenarios`, `recommendations`, `snapshots` |
| AI | `conversations`, `messages`, `agent_runs`, `tool_calls`, `memories`, `proposals` |
| Infrastructure | `jobs`, `webhook_events`, `audit_log` |

Tables from the brief that were deliberately *not* created:
- **Households and household membership.** Every row is owned by a single user today; sharing needs a consent model first.
- **Separate `merchants`, `forecasts` and `income_models` tables.** They are derived on demand, and the picture snapshot caches them.
- **Notifications.** No outbound channel is implemented yet.

## Old app's tables

The pre-2.0 app's tables in the `public` schema held no data. They were dropped when Link 2.0 was deployed, and no import from them exists.
